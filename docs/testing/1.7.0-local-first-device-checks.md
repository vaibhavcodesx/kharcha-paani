# 1.7 local-first phone checks

These checks cover the proposed local-first changes in [AI #226](https://github.com/vaibhavcodesx/kharcha-paani/pull/226), [local mode #230](https://github.com/vaibhavcodesx/kharcha-paani/pull/230) and [complete backup #227](https://github.com/vaibhavcodesx/kharcha-paani/pull/227). They are preparation, not a published 1.7 build or a passed phone test. The existing [1.6 device checklist](1.6.0-device-checks.md) still applies. Account/session changes require owner review before release.

## First: keep a safe copy

Use test data or a second phone for restore testing. Keep your original export untouched. A complete export is **not encrypted** and contains financial history and bill photos. Store it privately. Do not uninstall the only copy of your real ledger just to test restoring.

## No account

- At welcome, turn airplane mode on and tap **Use without an account**. No Google picker should open.
- Add an expense, income, two local friends, a local group, a split, an IOU and a subscription. Split ₹100 three ways: shares must add to ₹100 exactly.
- Close and reopen the app, then restart the phone. Entries and balances should remain. Widgets and reminders should use this same local ledger.
- Shared-group creation, invites, cloud sync and Gemini should explain that sign-in is needed. Ordinary entries, local splits and ordinary Insights should work offline.
- Settings should say **On this phone**. Cancel Google sign-in: local data stays selected. Complete sign-in, then choose local mode again: each ledger retains its own entries and photos. Nothing is automatically uploaded or combined.
- Swipe an expense away and immediately switch modes while Undo is visible. Reopen its original ledger: deletion should finish there, never affect the other ledger, and never crash.

## AI choice

- While signed in, accept the existing disclosure if needed, then turn **Use AI (Google Gemini)** off in Settings.
- Try typed Quick Add, bill photo, statement, an Insights question, trip review, a shared screenshot/PDF and widget Speak. None should send data for AI processing. Manual capture and saving a photo attachment should still work.
- Restart: Off should remain. Switch Off during a slow response: no late result should replace your edited draft.
- Enable AI: capture should identify Gemini, and first-use disclosure must still appear if never accepted. Turning On is not disclosure consent. External keyboard dictation is outside the app's setting.

## Export everything

- Populate a test ledger with duplicate friend names and identical purchases, local and shared group history, settled/pending/disputed payments, edited entries, subscriptions, custom categories/payment methods, UPI details and several bill photos.
- Settings → **Export everything**. Read the privacy warning. Cancel once: nothing changes and no destination opens. Try again, choose a private destination and save the JSON file.
- On a second installation with an **empty local ledger**, choose **Restore from a backup**, select that file, check the preview counts, then restore. The original source remains unchanged.
- Compare every saved entry, relationship, amount, latest edit, settlement status, subscription checkpoint, categories/defaults, sort choice, UPI details and photo. Shared history is a read-only offline copy; it must not grant membership or queue uploads.
- Confirm the target's AI Off choice remains Off. Login tokens, AI/crash disclosure acceptance and OS permissions must not be restored from a file.
- On test data, delete a friend who was recorded as a guest in an older split, export/restore, then add a different friend. The new friend must not inherit that old history or debt.
- While a swipe deletion is still finishing, restore should ask you to wait; it must keep Undo available and must not lose a restored photo. Retry after cleanup.
- Try restoring again into the now populated ledger: it must refuse to replace anything. A damaged, newer-format or oversized file must leave entries unchanged.
- Interrupt a test restore by closing the app, then reopen. It should finish from its private recovery journal or show a clear retry message, never duplicate rows or lose photos. If recovery cannot finish, keep the original archive and report it; do not delete app data.
- An older v1/v2 local backup should still show its original additive preview and restore missing local records.
