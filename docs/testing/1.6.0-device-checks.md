# Kharcha Paani 1.6.0: what to check on your phone

Nothing since 1.5.0 has been accepted on a phone. This is the combined, deduplicated phone list
for **every merged PR in `git log v1.5.0..main`**, through `c0c798d` (#191), including the
earlier fixes and account deletion (#103), not just the last solo queue. Sources are below.
The 1.6.0 release build has **not yet been made**; this document does not claim an APK is available.

Do section 0 first. Tick boxes and send back the item numbers and what happened; screenshots help.
Use invented entries and a test group for money changes. Never clear data or uninstall the owner's
1.5.0 installation to make a check pass. A second phone/groupmate is needed where marked.

## Before installing: owner release steps

The current [release workflow](../../.github/workflows/release.yml) **publishes a GitHub Release**;
it has no draft option. Codex must not dispatch it. After R1/R2/R3 have merged, version 1.6.0 (7)
is on `main`, and its exact commit has green CI, the **owner** does this:

1. GitHub repository → **Actions** → **Release APK** → **Run workflow** → branch **main**.
   Enter tag **v1.6.0**; check **prerelease** for this phone-test build; click **Run workflow**.
   Prerelease still publishes publicly. Do not rerun blindly if the workflow fails or the tag exists.
2. Open the run and confirm tests, signed APK/bundle verification and release creation all passed.
   Then repository → **Releases** → **Kharcha Paani v1.6.0** → download
   `KharchaPaani-v1.6.0.apk`. Use the APK for this phone, not the `.aab`.
3. Install **over 1.5.0, without uninstalling**. If Android refuses the signature, stop and report it;
   do not erase the existing ledger. With a USB-connected real phone, the optional
   [release smoke script](../../scripts/release-smoke.sh) checks the release certificate, installs
   with data retained, cold launch, shared text, an invite and background widget refresh. Its
   scripted success does not replace the manual checks below. No emulator is needed.

## 0. First checks (important)

- [ ] 0.1 Before updating, note several existing entries, friends, groups, balances and bill photos.
      After installing over 1.5.0, all remain unchanged. Cold launch works; Help & about and Android
      app information show **1.6.0 (7)**. Visit Home/Activity, Splits and Insights without a crash.
- [ ] 0.2 **Release-build Google sign-in:** sign out, sign back in and confirm the same ledger returns.
      In airplane mode, a sign-in failure first suggests reconnecting; reconnect and retry. Dismiss
      the picker without an error; where applicable, the no-account guidance explains adding one.
- [ ] 0.3 **Quick add through the server proxy: never verified end to end from a real phone.**
      Online, accept the Gemini notice and read a new quick-add line, a bill, a statement and an
      Insights question. Confirm useful results, full amounts and dates. An offline/manual result
      alone does not prove the proxy worked; record any fallback/error. Do not expose keys or logs
      containing personal documents. The owner must confirm server deployment/configuration.
- [ ] 0.4 **Say the split, from both widgets:** text `petrol 500 <test group's name>` opens that group
      with its members selected; voice `dinner 1800 with <friend's first name>` selects that friend
      and gives ₹900 each. Check chips before saving. `chai 40` stays personal; an unknown or
      ambiguous friend gives guidance rather than a guessed member. Repeat offline to check local fill.
- [ ] 0.5 **Preselected shared group:** start a split with a friend with history. The most recent
      active group selects just you and that friend. Is the chosen group obvious **before Save**,
      so you know its shared members will see the expense? Change group/choose No group, then change
      participants: your choice stays. Editing or starting inside a group keeps its group; no-history
      friends get no unrelated/archived group. Save only in the test group; verify members and shares.
- [ ] 0.6 **Crash-report switch:** Account → Help & about → Send crash reports → off. Close/reopen
      the sheet and restart: still off. A build without Firebase configuration should hide the row;
      record that as unavailable, not proof reports were sent. Only the owner can confirm receipt
      in Firebase Console → Crashlytics when configured; do not deliberately crash the real ledger.
- [ ] 0.7 **Friendly partial Ask:** ask for part of a test friend's balance. The preview says exactly
      `Asking ₹X of the ₹Y for now.` with the real figures and no “you owe”. Share to yourself:
      caption, payment-code image and label remain intact; cancelling the chooser does not mark it
      asked. Asked today/yesterday/day-count and tapping history keep the right friend/balance.

## 1. Delete my account — THROWAWAY GOOGLE ACCOUNT ONLY (important)

**Never do this with the owner's account.** The owner must first confirm #103's migration/server
setup and SQL-editor results; a merged PR does not prove a live migration. Use a separate test
installation/device/account so the retained owner ledger from 0.1 is not put at risk.

- [ ] 1.1 With a throwaway Google account, join a group with a second phone; add a shared expense
      and note both phones' balance. Account → Delete my account → read consequences → leave
      **Former member** selected → Continue → confirm. This action is destructive.
- [ ] 1.2 The test phone returns to sign-in. Signing in again with that throwaway account starts empty.
      On the other phone after sync, shared history remains, the balance is unchanged, and the
      deleted participant reads **Former member**. Report failures; do not repeat on a real account.

## 2. Entries, amounts, bill photos and AI

- [ ] 2.1 Enter `1,200`: ₹1,200 saves. Pasting `1e999`, `NaN` or a 20-digit number is refused; a
      third decimal is refused. Above ₹10 lakh, expense/settlement/IOU Save asks to check the extra
      zero; Change it returns, Yes, save writes once. Future dates cannot be picked.
- [ ] 2.2 Double-tap Save, shared Create group and Record settlement: one record each. A bill-photo
      save shows its busy state. Successful entry/payment/import gives one confirmation haptic;
      invalid amounts and empty imports give none; Android touch-feedback off is respected.
- [ ] 2.3 Home → Bill photo opens the picker; cancel changes nothing. Pick/capture a bill, save,
      reopen Edit: saved photo appears. Open/zoom/replace/remove, including missing/local/saving
      states. Discard/Keep editing and Cancel do what they say; swipe/edit/delete/Undo still work.
- [ ] 2.4 On a fresh **test** install/account state where notice acceptance is unset, quick add first
      shows the Gemini disclosure. Type it myself fills locally and leaves manual entry usable;
      a bill keeps its photo, a statement/Insights/trip read does not run. Got it allows AI; subsequent
      attempts do not repeat the notice. Do not clear the owner's data to reset this check.
- [ ] 2.5 Check Insights/trip question empty/loading/retry/error states and that existing answers
      remain. Offline/failed bill/quick-add reads give specific guidance. Report this answer opens
      an email draft with question, answer, line breaks and phone/version details; back out without
      sending. If intentionally testing the daily statement cap, the fourth read shows today's
      reads-used-up guidance; do not count a local fill as a successful server read.
- [ ] 2.6 Beverages, Packaged goods and Self-care have distinct icons/colours. `haircut 300` selects
      Self-care, `juice 60` Beverages; existing categories stay unchanged. Category/payment-method
      defaults, hide/show/remove, duplicate/length guards and custom apostrophes/percent signs work.
- [ ] 2.7 Entry fields, payment method and expense/income rows retain notes, merchant, visit labels
      and full paisa. Self reads You in payer/editable/locked split summaries. Short/over-total
      splits disable Save; a valid equal ₹500 split three ways adds up to **₹500.00**, also outside
      shared groups. Save preserves selected IDs, category, method, group and amount.

## 3. Friends, groups and payment history

- [ ] 3.1 Groups → Where it went → Food shows only this group's Food entries, newest first, with
      full total/share. Tap again to close; another category replaces it. Editable rows open the
      correct entry; another group's categories start closed; archived entries stay read-only.
- [ ] 3.2 Groups → Sort: try all five choices, including similar names/opposite balances. Restart:
      choice stays. New/confirmed activity moves Latest activity; archived groups remain openable.
      Payer/member dots match friend/account colours; guests/former members/long names stay distinct.
- [ ] 3.3 Group → Settlements shows dates, people and pending/confirmed/rejected statuses, IOUs and
      payments between other members. Viewing changes no balances. All activity restores expenses;
      archived/empty histories are clear. Adder/payer credit uses the actual person, including former
      members. Who pays whom retains names, direction and full figures.
- [ ] 3.4 Expand a long multiline IOU: whole note, full date/time and saved recorder are readable.
      Old records with no recorder say unavailable; never guess. Others' IOUs offer no removal;
      pending records still open the answer sheet. Friend history's count, signed amounts, totals,
      pending/rejected explanations, age and quoted notes agree with its balance; Settle opens that friend.
- [ ] 3.5 Retract/Delete IOU/Withdraw/Clear asks first and states the right amount, balance consequence
      and sync scope; pending/rejected records say they did not count. Cancel/Back changes nothing;
      confirm removes the intended test record. Local Delete group confirms and keeps history;
      shared groups offer no delete. Friend removal also states consequences; cancel preserves records.
- [ ] 3.6 Create a local group with a selected friend: correct members/title save. Share with others
      explains local-member visibility; blank/overlong shared names disable Create. Invite preview
      retains inviter/count, quoted group name and code/link; join/leave, guests and eligibility work.
      Offline/expired-code/session/member notices remain specific; dismiss/retry works. Use test groups.
- [ ] 3.7 Record payments/IOUs in both directions and confirm/reject a pending shared payment: intended
      balance/note changes once. Activity search finds friend-related records, displayed payment
      titles and exact amounts with/without ₹/commas, paisa and a personal share. Unrelated rows stay
      out; filters/clear restore the feed. “Edited by X” is still a follow-up, not a shipped claim.
- [ ] 3.8 UPI card: setup guards/payee name, your/their code, exact/Any amount, full spoken
      amount/payee, Copy ID and installed-app chooser work. Inspect without making a real payment.

## 4. Statements, export, backups and subscriptions

- [ ] 4.1 Start a long statement read. Back, Cancel and tapping outside close it promptly; no late
      result reopens it. Waiting about 20 seconds shows the longer-reading explanation; letting a
      read finish still opens review.
- [ ] 4.2 Review several months/date formats against the source. Impossible/unreadable/future dates,
      large income and outside-period rows have the correct warning and start unticked. Unknown
      flags/period text, including percent signs, stay intact. Cancel/reopen: dates stay stable.
      Change categories; tick zero/one/several rows; counts, month groups and disabled state match.
      Import writes only selected rows. **Automatic statement re-import deduplication (#130) is not
      in this baseline; do not import a real statement twice to test it.**
- [ ] 4.3 Export by month, date range and Everything: counts/enabled state match; CSV columns/amounts
      are intact. Backup summary/preview date/version and singular/plural counts are correct,
      including Settings only. Invalid backup gives a reason and changes nothing; Cancel changes
      nothing. Restore a test backup twice: only missing records added, no duplicates, useful counts.
- [ ] 4.4 Add a test subscription with a past start: cycle/first-charge wording and both backdate
      choices have the intended amounts. Cancel/Keep it and removing a cancelled row still work.

## 5. Notifications, privacy, widgets and sharing

- [ ] 5.1 On Android 13+, use a fresh **test** install for permission checks: first-entry offer → Not
      now gives no Android dialog; shared-group/payment offer → Turn on shows it. No third offer.
      After permission is denied twice, Account → Notifications → Turn on opens system settings.
      Status, payment warning, daily time and default 22:30–08:00 quiet hours are clear and editable.
- [ ] 5.2 Both channels exist after first open. Block Payments to confirm: no reminder; unblock/sync:
      it arrives. Payment toggle off/quiet hours suppress without spending the reminder. A payment
      confirmed/withdrawn on another phone loses its notification after sync/reopen. Answering clears
      it. Daily and payment copy/channel labels are intact; tapping opens the correct action.
- [ ] 5.3 Lock screen with sensitive content hidden: generic payment reminder, no person/amount;
      unlock shows full details. Android 13+ Recents hides ledger preview; an in-app screenshot works.
- [ ] 5.4 Place both widgets: labels, actions, full amounts and spoken spent/today totals match the
      app; refresh while app is backgrounded. Signed out shows no previous account's figures and
      offers sign-in. Widget Add/Splits/mic still open the right place.
- [ ] 5.5 Share Gallery image, Files PDF and bank-like text: correct review opens. Outgoing CSV/QR
      share works. Optional with an intent test sender: an image/PDF using this app's own FileProvider
      is refused with a generic file error; ordinary content shares continue working.

- [ ] 6.2 At 200% font size, tabs/Add remain tappable; group balances/long names, Insights cash-flow,

- [ ] 6.3 TalkBack announces tab name/selection, Add, Account/sync waiting/error counts (silent when
      fully synced), month navigation limits, chart/day/category totals, participant/self names,
      payment methods, photo actions, expanded state, deletion and answer actions. Friend colour
      hue/shade/previous/next controls and full custom apostrophe/percent names remain understandable.
- [ ] 6.4 Insights current/past/empty months, one/many category counts, percentages (single %), ring
      drill-down and previous/next month show the right data. Friendly labels/counts on all touched
      screens match the existing English; no raw resource placeholders appear.
- [ ] 6.5 Sign-in agreement/18+ line, Terms and Privacy open the intended pages; report a broken URL.
      Signing in disables Continue; Dismiss works. Help & about → feedback opens an addressed draft
      with device/version; licences list and linked licence pages work. Nothing sends automatically.
- [ ] 6.6 Duplicate friend, unreadable file, refused save, missing camera and Undo have useful
      unchanged notices; retry works. Ledger-open failure, if encountered, offers Retry/Sign out
      without deleting data; do not manufacture corruption in the owner ledger.

## 7. Can't be checked on a sideloaded APK

These need a **Play-installed test-track build**, later owner track setup and, for updates, a higher
version on the same track. A GitHub APK cannot establish success. Play may suppress review UI.

- [ ] 7.1 Flexible update: decline without blocking ledger/repeating on each foreground; accept and
      continue using the app during download. Background/return restores ready notice. Save/close
      drafts, then explicitly Restart; new version and ledger intact. Sideload/network errors never
      block entry. The update must not interrupt a draft/sheet.
- [ ] 7.2 Review: only an eligible successful confirmed settlement after settling-in may request it;
      history, pending payments, IOUs and failures do not. No sheet/draft/error overlap or immediate
      repeat after reopening/account switch; cancellation/network failure changes no money. Known
      F1 timing follow-up remains to be checked after its fix; absence of Play UI alone is inconclusive.
